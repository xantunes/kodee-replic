# Brainstorming

## When to Use
Before any creative or building work. Use when requirements are unclear, a new feature is requested, or architectural decisions are needed.

## Purpose
Explore requirements, constraints, and possible approaches before committing to an implementation plan.

## Instructions

1. **Understand the goal:** What is the user trying to achieve?
2. **Identify constraints:** Existing codebase, tech stack, time, dependencies.
3. **Explore options:** List 2-3 viable approaches with trade-offs.
4. **Ask clarifying questions** if requirements are ambiguous or underspecified.
5. **Get design approval:** Present options and let the user choose before proceeding to `writing-plans`.

## Output
- Brief summary of explored options
- Recommended approach (if clear)
- Any open questions for the user

## Critical Rules
- Do NOT start implementation during brainstorming.
- Do NOT write plans until the approach is approved.
- If the user says "just do it" or provides very specific instructions, skip to `writing-plans`.
