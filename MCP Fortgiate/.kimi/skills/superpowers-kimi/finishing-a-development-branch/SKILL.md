# Finishing a Development Branch

## When to Use
When all tasks are complete and verified. Use before presenting the final result to the user.

## Purpose
Perform final review, cleanup, and present the completed work professionally.

## Instructions

1. **Final review:**
   - Re-read the original request
   - Confirm all requirements were addressed
   - Check that `SetTodoList` shows everything as `done`
2. **Cleanup:**
   - Remove any temporary files created during development
   - Revert any unintended changes
3. **Summarize the work:**
   - What was done
   - Files changed
   - How it was verified
4. **Present options** (if applicable):
   - Next steps
   - Potential improvements
   - Alternative approaches considered

## Critical Rules
- Do NOT claim completion until `verification-before-completion` has passed.
- Keep the summary concise — the user wants to know what was done and why, not a play-by-play.
- If the user provided a plan file or todo list, ensure it reflects the final state.
